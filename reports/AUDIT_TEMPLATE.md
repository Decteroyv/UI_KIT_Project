## Гипотеза о причине

Основная причина нестабильности — vendor CSS подключён без каскадного слоя. Обычные авторские объявления без слоя имеют приоритет над обычными объявлениями в именованных слоях, поэтому даже сложный компонентный селектор проигрывает vendor-правилу. Дополнительно встречаются глобальные селекторы, чрезмерная специфичность, жёсткие размеры, повторные блоки и неверно выбранные семантические состояния.

`@layer` задаёт предсказуемый приоритет между группами правил одного происхождения и уровня важности. Он не исправляет ошибки HTML/JS, не отменяет inline-стили и не делает безопасными `!important`. Для important порядок слоёв обратный, поэтому такие объявления нужно устранять, а не маскировать.

## Три трассировки каскада исходного проекта

### 1. Primary button в `#workbench`

- Свойство: `background`.
- Кандидаты: `#workbench .ui-button` из unlayered vendor CSS (author normal, специфичность `1-1-0`) и `.ui-button--primary` из `components` (author normal, `0-1-0`).
- До исправления выигрывает unlayered vendor-правило: слой сравнивается раньше специфичности; unlayered normal выше именованных слоёв.
- После исправления vendor находится в `legacy`, а `components` расположен позже. При одинаковом origin/importance выигрывает слой `components`; правило Primary берёт цвет из семантического токена.

### 2. Danger tag во вложенной карточке

- Свойства: `background`, `color`, `padding-inline`.
- До исправления участвуют `.is-danger` из нескольких файлов и `:is(.ui-card, #workbench) .ui-tag`. В `:is()` специфичность определяется наиболее специфичным аргументом; ID поднимает вес селектора. Vendor-правило `.is-danger` также находится вне слоя.
- После исправления общий `.is-danger` удалён. Тег оформляется только `.ui-tag--danger`; карточка не стилизует произвольные потомки, а `legacy.css` не адресует Atlas-компоненты.

### 3. Required input до взаимодействия

- Свойство: `border-color` и `background`.
- До исправления `.ui-field:has(input:invalid) input` совпадает с пустым required-полем сразу при загрузке.
- После исправления JS не ставит `aria-invalid` до blur или submit. CSS использует `.ui-field:has(input[aria-invalid="true"]) input`, поэтому начальное состояние нейтральное, а ошибка появляется после взаимодействия.

## Вывод

Большинство дефектов были не косметическими: они нарушали границы владения компонентами, доступность, адаптивность и предсказуемость каскада. Исправление выполнено через слои, scoped vendor CSS, семантические токены, модификаторы и ограниченные селекторы. Поведение диалога и момент отображения ошибки исправлены в JavaScript/HTML, поскольку эти требования нельзя корректно решить только CSS. Статические проверки проходят; браузерную регрессию и снимки на всех ширинах необходимо подтвердить локально в браузере.
