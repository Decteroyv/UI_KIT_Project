# ADR-001. Управление приоритетами каскада

**Статус:** принято  
**Дата:** 18.11.2026  
**Контекст:** объединение библиотеки ATLAS UI с унаследованным CSS подрядчика.

## Контекст проблемы

В исходном проекте vendor CSS был импортирован без слоя. Его обычные author declarations выигрывали у компонентных правил, даже если у компонентного селектора была меньшая специфичность. Дополнительные конфликты создавали `#workbench .ui-button`, `.is-danger`, `.ui-card p` и ID внутри `:is()`.

## Рассмотренные варианты

| Альтернатива | Плюсы | Риски | Решение |
|---|---|---|---|
| A. Один общий CSS-файл | Просто начать | Смешиваются роли, порядок становится неявным, растёт дублирование | Отклонено |
| B. Только БЭМ и регламент | Понятные имена и модификаторы | Сам по себе БЭМ не изолирует глобальный/vendor CSS и не задаёт приоритет слоёв | Используется как часть решения |
| C. `@layer` + токены + контракт компонента | Явный приоритет, разделение ответственности, темы через семантические токены | Нужна дисциплина при добавлении новых слоёв; important требует отдельного анализа | Принято |
| D. Только CSS Modules | Локальность классов в сборке | В проекте нет сборщика; не решает порядок внешних стилей, глобальные токены и нативную семантику | Отклонено для этой работы |

## Решение

Порядок слоёв объявлен один раз в `css/app.css`:

`reset → legacy → tokens → base → components → states → utilities`.

Все таблицы стилей импортируются в соответствующие слои. `legacy.css` сохранён, но его селекторы ограничены `.legacy-zone .legacy-widget`; он не адресует `button`, `input`, `#workbench` и классы Atlas UI.

- **Специфичность:** начинать с классов и низкоспецифичных `:where()` для reset; не использовать ID для оформления компонентов; не смешивать ID в `:is()`.
- **Публичные классы:** `.ui-button` + `--primary|--secondary|--ghost|--danger|--sm|--lg`; аналогично `.ui-card--featured`, `.ui-tag--*`, `.ui-alert--*`.
- **Состояния:** `:hover`, `:active`, `:focus-visible`, `:disabled`; ошибка формы задаётся через `aria-invalid="true"` после взаимодействия.
- **Границы:** компонент не оформляет произвольных потомков. Для текста карточки используются прямые дочерние селекторы; для вложенного Alert действуют его собственные классы.
- **Третий party CSS:** остаётся включённым и изолированным в `legacy`-слое, виджет не удаляется.

## Почему не `!important`

`!important` не добавляет специфичности, а меняет уровень каскада; для important порядок слоёв обратный. Массовое добавление important создаёт новую гонку приоритетов и затрудняет расширение. Правильное решение — изолировать источник и исправить контракт.

## Где одного `@layer` недостаточно

Слои не исправляют неправильную семантику HTML, `display:none` у keyboard control, преждевременную валидацию, немодальный `dialog.show()` и слишком широкие селекторы внутри одного слоя. Эти дефекты требуют изменения CSS-селекторов, HTML или JavaScript.

## Последствия и риски

Новый vendor stylesheet следует импортировать в отдельный или существующий vendor-слой, проверить отсутствие unlayered правил и important, а затем прогнать архитектурные и браузерные регрессионные тесты. Изменение порядка слоёв — потенциально breaking change и должно сопровождаться обновлением ADR и тестов.
